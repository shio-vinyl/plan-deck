# 视觉与版式

出工作稿时 agent 只在一个固定框架里设计（设计决策 3）；定稿后的收尾另有规则，见 `humanize.md`。约束从上到下分四层：

1. **结构大纲**：有哪些页、每页标题是什么（设计决策 11）。
2. **页面框架**：页眉、网格，全册一样，由大纲和项目信息生成。
3. **版式**：从清单里选一种，不自由摆放。
4. **组件**：图示、表格、指标数字、卡片，按规定的场合和外观使用。

原则是**不减内容，增加结构**：每页三四百字是汇报对象需要的信息量，不能为了好看砍掉，要做的是“密而不乱”。

**工作稿按本文的一致性规则做。** 只有用户确认定稿后做了去 AI 味的那一版例外：页眉、标题层级、页码、字号下限、红色表示重点仍然全册一致，配色、模块尺寸、线型、页面骨架放开（决策 18，`humanize.md`）。

## 页面框架

- **页眉**：两行标题。上一行是上级节点名，下一行是本页节点名，两行同色、同粗，本页一行字号小一级；总览页只有一行。标题区下方一条细线。不用小字面包屑，看不清。
- **通栏页眉**（`banner` 预设，`architecture.md`“预设”）：顶部一条深色通栏；第一行写章名（和正文同字号、加粗，不比正文小），下面是节名（大字，左侧一条竖色条）和页名，再一条细线；右下角自动页码。章名行是页眉的一行，全册同一位置，不是页角标签，也不是面包屑。用这个预设时页码从工作稿起就有。
- **正文区**：页眉以下的版心，按 12 栏网格划分，栏间距固定。所有元素的边落在栏线上。
- **默认不加的**：页脚、页角的章节标签、资料来源小字。依据写进正文；默认页眉的页码等整份汇报定稿时再按需要加。
- **结构页**：封面、目录、章节页、致谢页各有一种固定样式，内容来自大纲和项目信息。章节页可以重放目录并高亮当前章。

页眉由运行时按 `style.json` 画，不手写、不改样式。结构页运行时还没有，在脚本里按固定样式做，全册统一（`page-types.md`“结构类”）。

**模块稿**：只做别人汇报中的一段时，所在章号未定就用 x.1、x.2 占位，拼入时再换；不做封面、目录、章节页、致谢页。

## 版式清单

每个内容页只用一种版式。版式里的区域可以放组件，但不再嵌套另一种版式。

| id | 名称 | 构成 | 用途 |
|---|---|---|---|
| `split` | 图文二分 | 一侧文字，一侧图（地图、照片、图表）或表；按栏数分 6/6、4/8、8/4，左右可换。文字栏用 ■ 小标题分段，图占满栏高 | 现状、问题、方案、单张地图页，用得最多 |
| `full-image` | 满版图 | 图铺满正文区或整页，文字放在图上一块区域里，文字区不超过页面三分之一；字下要压暗时垫渐隐暗带，不压大块不透明色底（章小结页见 `page-types.md`） | 区位、愿景、方案总图、效果图、章小结 |
| `diagram` | 图示 | 正文区整块放流程图、框图、逻辑链或时间轴，可在一侧留一栏说明 | 政策路线、办理流程、体系框架、进度安排 |
| `table` | 表格 | 正文区整块放表或矩阵，可在一侧留一栏说明或配小图 | 对比、清单、指标、用地平衡 |
| `columns` | 多栏并列 | 2–4 栏等宽的平行条目，栏头是编号或标题加一条色线，栏间靠留白或细竖线分开；顶部可加一条流程箭头把各栏串起来 | 策略一二三、案例对照、对标、要素 |
| `gallery` | 多图组 | 2–6 张照片或小地图，同尺寸、对齐，每张配图注；可留一栏文字 | 现场照片、逐级区位图、方案比选、同底图专题 |

内容放不进任何一种版式时，agent 停下来问用户，不自己发明版式；确实需要新版式，先和用户确认，再补进本表。各页型常用哪种版式见 `page-types.md`。

## 字号层级

全册只用几级字号：正文、小标题、本页标题、上级标题，色块里的关键词（中间层），以及大字、大数字。正文到上一级至少差约 1.25 倍；小标题以上各级至少差约 1.15 倍（如 18、22、26 磅），不在中间插值。

- **中间层**：色块、栏头、标签里的关键词用 `key` 级（19.05 cm 页高 18 磅左右），三五个字的大字栏头和大数字用 `figure` 级（24—30 磅）。正文多的页都要有这一层，`inspect` 对正文 200 字以上却没有 14 磅以上字的页警告（`patterns.md`）。
- **矩阵表例外**：表格按版心在正文的 1—1.25 倍里选一个放得下的字号（`matrix`），只用于表格内。

- **页面上没有比正文小的字**：图注、表格、标注、时间轴、图示里的短语都用正文字号。
- **正文以投影可读为准**：33.9×19.1 cm（PowerPoint 默认 16:9）页面不小于 12 pt，52.8×29.7 cm 页面约 18 pt，其他尺寸按页高等比换算。
- **不用细体，次要文字不能太浅**：灰色次要文字也要在投影上看得清。

反例：正文、小标题、标签分别用 16、17、18、19、20 pt，层级分不出来，只显得密；图注、来源用 9–10 pt 小字，投影时看不清。

**例外：地图图面内的注记。** 一张图要标几十个地块、单元、项目，用正文字号排不下，也会盖住图面，所以图面里的注记可以小于正文，下限由项目视觉系统定（`style.json` 的 `mapText`）：

| 注记 | 默认下限（19.05 cm 高的 16:9 页面） | 例子 |
|---|---|---|
| 对象标注（`labelPt`） | 10 pt | 地块编号、项目名、单元名 |
| 次要注记（`minorPt`） | 9 pt | 道路名、片区名、水系等底图注记 |

- **按放进页面后的实际尺寸计**：图上注记的 pt 乘以放图的缩放比例。gis-composer 按厘米出图、原尺寸放进页面时，主题定的字号就是页面上的 pt（1 px = 0.75 pt）；缩小放图，注记跟着变小，运行时会报出缩小后的字号。
- 其他页面尺寸按页高等比放大（52.8×29.7 cm 页面约 15.5 pt、14 pt），项目可以在 `mapText` 里另定，理由写在 `style.md`。
- **只限图面里的注记。** 图例、图注、指北针旁的说明、指标表都是页面元素，仍用正文字号；图例画成页面上的可编辑形状（`architecture.md`“地图衔接”），不画进图里。

## 字体

整册字体在 `style.json` 的 `fonts` 一处定：`cjk`、`latin` 是页面用字，`map` 是地图图面用字。选哪种字体、为什么，写在项目的 `style/STYLE.md`，没有 `STYLE.md` 时写在 `style.md`（`architecture.md`“项目视觉系统”）。各字体的真实字重、许可、字形覆盖，以及 PowerPoint 缺字体时怎样替换，见 house-style skill 的 `references/fonts.md`，这里不重复。

- **地图能用页面字体时就用页面字体**，同一页上只有一种黑体。前提是：字体许可允许用在地图出图里（图片随汇报分发）；gis-composer 能加载本地字体文件；字形覆盖够用，规划常用的 ㎡、①②、生僻地名都有字形。
- 做不到时（比如页面字体的许可不允许拿到 Office 以外出图），地图用一种同类的无衬线体（如思源黑体），`fonts.map` 写明，理由和页面字体写在一处。这是已知的取舍：同页两种黑体，笔画粗细略有差别，但地图注记小、图面自成一块，不影响阅读。
- 地图主题的字体照 `fonts.map` 设，不在地图项目里另选。运行时在 `style check` 和放图时核对，对不上会警告（`architecture.md`“项目视觉系统”“地图衔接”）。
- 页面字体是不是真的用上了，交付前用 PowerPoint 渲染核对：`plan-deck render --engine powerpoint --style style.json` 列出 PDF 里实际嵌入的字体，有 `style.json` 没定的字体会警告。

## 配色

配色由每个项目的视觉系统决定，不规定具体色值。风格按用途选，分两种就够：

- **实用汇报**：给主管部门、领导看的工作汇报，目的是讲清楚、好核对。可以用一套多色系统帮助分类，强调要明确。
- **讲究美感**：竞赛、对外展示等要体现高级感的场合。可以白底黑字、几乎不用颜色，靠图片和留白取胜。

用途在项目开头定视觉系统时一并定下，全册统一。配色的取向，每种颜色表示什么、取自哪里，写在项目的 `style/STYLE.md`，没有 `STYLE.md` 时写在 `style.md`（`architecture.md`“项目视觉系统”）。无论哪种，都守这几条原则：

- **可读**：文字和底色对比足够，图上的文字不被底图吞掉。
- **强调要有落点**：强调色用在条目的引领词、关键短语、关键数字和范围线上；正文里按条目计，一般每条一处（“页面文字”）。整段、整栏标红等于没有强调。
- **全册一致**：同一种含义全册用同一种颜色，地图与页面同一套色。
- **按含义命名**：页面上的颜色按它表示什么起名（账算式的“新建”“扣除”、漏斗各级、浅色底、表格高亮行），不按色相起名（“蓝”“灰”）。改一种含义的颜色只改一处，不会连带改了别的含义。色相名只放 `palette`；`colors`、`classes` 按色相起名时 `style check` 警告。
- **一种颜色一类内容**：类别色贯穿一组页面的图示、栏头和表头，同一种颜色在同一页、相邻页不表示两类内容。类别色从 `classes` 取，运行时才能查出同色异义。
- **一处定色**：地图也用的颜色（强调色、类别配色）定在地图主题里，页面从主题读；只在页面上用的颜色定在 `style.json`。两边不各抄一份（`architecture.md`“项目视觉系统”）。
- **地图配色守行业惯例**：用地分类色、三线配色等按标准和习惯来，不随项目风格改（见 `map-types.md`）。

## 框和卡片

正文段落和条目直接排在页面上，用 ■ 小标题、加粗、强调色关键词和强调色大号数字区分层级，不套底色框。框只有下面八种角色：

| 角色 | 用在哪里 | 外观 |
|---|---|---|
| 图示节点 | 流程链的步骤、层级框的层级、并列要素宫格、矩阵的行列标签 | 实色或浅色填充；框里写短语，一般不超过两行；同一张图里同级节点同尺寸、同颜色，颜色表示类别或层级；框与框之间有箭头、加号、嵌套或对齐关系，箭头和连线全册一个样式 |
| 摘录框 | 政策原文、文件要点，与旁边的文件截图对应 | 细线框，不填充或极浅填充；关键句用强调色；注明出处 |
| 账算式 | 确实在算账的页面 | 色块装大号数字、单位和一行说明，方块之间放运算符；同一个等式里方块同尺寸 |
| 标签行 | 2—5 条并列、各有短名的条目（环节、文件、案例），一册不超过一成的页 | 左边实色块写短名，右边正文（浅底或白底细线），行高按内容、铺到底（`patterns.md`） |
| 表格 | 对比、清单、指标 | 表头深色填充或加粗底线，行间细线，不画全框网格；数字右对齐，合计行加粗 |
| 分组底 | 把一组内容归在一起，例如把几个案例按所属体系分成两组对照 | 浅色填充、无边框，左上角写组名；组内的元素按自己的角色排，不再套框 |
| 结论通栏 | 本页要放大的判断或共同点，一页至多一处 | 一两句话；整块实色或大字，不用浅底加左色条。写法见“每页三层” |
| 色块卡片 | 几项并列的同类内容，字不多，颜色表示类别，例如四个机制各一张 | 整块实色填充，白字，无边框；名称、一两行说明；高度按内容定。底色上不标红，重点用白色加粗 |

所有框共守的外观：

- 直角，不加阴影、渐变和描边光效；
- 填充和线框二选一，不同时用；
- 框的大小按内容定，内边距固定，不按网格均分后留一大片空；
- 同一种角色全册一个样子。

多栏并列（`columns` 版式）默认不用框：栏头用编号、标题加色线，或整块实色栏头，栏与栏之间靠留白分开。

**卡片看时机用。** 土的是阴影、描边、圆角的卡片和浅底加左色条，不是整块实色。判断方法：这几项是不是并列的同类内容？颜色有没有表示类别？字够不够少，放得进一张卡片？三条都满足就可以用色块卡片；内容多、要逐条核对的，还是排成正文或表格。

以下是通用 PPT 的写法，规划汇报里没有，会让汇报显得像 AI 做的：

- 一段正文一个浅底框，再加左侧色条或标签块，而且成了每页的做法（标签行一册不超过一成的页，`inspect` 会警告）；
- 每页都在页底加“存在问题 / 结论 / 回应”栏；
- 框按网格均分尺寸，不按内容定，框内大半留空；
- 几张并列卡片之间没有关系，只是把文字分组；
- 圆角、阴影、渐变的“卡片风”，尤其是阴影加显著的卡片；
- 细框或浅底的等尺寸模块，形状和内容没有关系，只是把文字分组（`inspect` 会警告，色块卡片和流程节点也会报，看过判断）；
- 用标签块、小胶囊（chips）列要点；
- 大号装饰性符号，如“？”、大三角箭头（流程图里的箭头不算）；
- 细箭头：放在色块之间几乎看不见；
- 照片上压大面积的半透明或不透明色块，再叠字；
- 过渡页、总览页靠大数字、卡片填空白；
- 节一级的页面复用章节页的章号样式。

反例来自试做和改稿反馈。

**不加框不等于朴素。** 去掉卡片以后，页面的层次要靠这些手段：一套类别色贯穿图示、栏头和表头；能画成图示的不写成段落；图片和地图放大；关键数字用大号强调色；条目的引领词和关键短语用强调色加粗（“页面文字”）。只剩白底文字和细线的页面同样不合格（试点 01，Issue #4）。

**朴素了就加内容的分量，不加装饰。** 判断方法：去掉这个元素，读者少知道了什么吗？

| 可以用足 | 不要 |
|---|---|
| 证据物：地图、案例图、文件摘录、表、原生图表。纯文字页要有理由，政策类没有地图时用文件摘录、案例图、对照表 | 只为分组的卡片 |
| 图示：把流程、比例、对照画成图，让相关的东西对齐 | 阴影 |
| 实色块：图示节点、栏头、案例名标签、并列项的色块卡片，直角，按类别配色 | 彩色顶条加等尺寸浅底卡片的组合 |
| 底色带：把相关的节点连起来，如两个案例的同一环节 | 大留白的极简风格：撑不起每页三四百字 |
| 粗箭头：线宽和节点分量相称，默认 3 pt | 细箭头 |

## 页面文字

### 不当讲解员

页面是被讲的材料，只呈现内容；解释、串讲、点明重点由汇报人来做，放在讲稿里（`design-principles.md` 决策 13）。这是页面文字的总原则，下面的“标题”“措辞”都从它来。

**逐句问：这句话在说项目和政策本身，还是在告诉读者这页讲什么、该怎么看？** 后者不上页面。

| 讲解员在做什么 | 不用 | 用 |
|---|---|---|
| 告诉你这页在干什么 | 三清单回答三个问题；下表是三个案例的做法 | 三清单：能否转、转什么、怎么转；直接放表 |
| 替你总结意义 | 地价补缴规则：让企业事先算清“经济账” | 地价补缴规则 |
| 替你纠正理解 | 特色场景不是清单，是清单之外的专项通道 | 特色场景设专项通道办理 |
| 教你怎么读 | 怎么查：先选目标，再查对应一列；不在本表；本页假设 | 表能看懂就删；假设情形 |
| 替你点出重点 | 两个案例都没有收回土地，靠的是区政府逐案决定 | 两个案例均未收回土地，由**区政府逐案决定** |
| 带你一段段往下读 | 要解决什么；从案例看；规划怎么做；差额补缴怎么算 | 存在问题；案例做法；规划做法；差额补缴方式 |

常见信号：X 回答 Y、要解决什么、从……看、靠的是、要做的是、关键在于、不是 X 而是 Y、让……、把……变成。`inspect` 会警告其中一部分；讲解员能换说法，词表只作线索，还是要逐句读。

讲解员口吻和讨论口语只警告，不像“页面绝不出现”那样报为问题：同样的词常是正当内容（政策原文里的“不是……而是”、研究问题“如何……”、“关键在于”出现在引用里），真实汇报试跑误报多；报成问题会逼着改掉对的句子。逐条看过，确是讲解的就改。

**不算讲解的：**
- 带事实的结果句：“旧产业区更新潜力空间为 12.6km²”。
- 研究问题本身：“如何增加规划的弹性？”。它是研究内容，不是在带读者读。

**页内小标题按内容量选：**

| 写法 | 什么时候用 | 例子 |
|---|---|---|
| 名词小标题 | 内容多，要分块 | ■ 存在问题；■ 案例做法；■ 规则要点。真实汇报的说法：城市问题、更新方向、基本情况、权属情况 |
| 不用小标题，一段陈述 | 内容不多，一段就说清 | 直接写一段，接图示或表 |
| 小标题直接写内容 | 尽量少用，比前两种有 AI 味 | ■ 两个案例均未收回土地，由区政府逐案决定 |

### 每页三层

内容页一般有三层（决策 15）：

1. **一行红字结论：** 本页的观点或问题，是带事实的判断，20—24 磅（字号级别 `conclusion`，其他页面尺寸按页高等比），默认放在标题线下，用 `p.conclusion()` 画。它不是副标题，副标题的限制不适用于它。连续的清单页可以省。去 AI 味版里不必每页同一位置、同一形式（`humanize.md`）。
2. **放大的重点：** 整块实色、大字、大数字、粗箭头、结论通栏，一眼看到本页最重要的两三件事。共同点和问题要放大，不要单纯列表。按内容从 `patterns.md` 选做法（标签行、栏头并列、通栏、箭头链和节点链、泳道、文件摘录、矩阵表、台阶），账算式只用于确实在算账的页。
3. **密集的次要信息：** 12—14 磅，条款、时间、数字、案例、程序都留着，关键词标红。不能因为强调就把内容删少。

图示要大胆：流程、分工、判断路径用流程图、泳道图、粗箭头；问题和原因用大块分类；层级用金字塔或台阶；变化用前后对比。表格只用于清单条目和确实要逐行比对的内容。证据物（文件截图、地图、案例图、现状照片）要多、要大，优先取过往稿子里已有的图。

版面铺到版心底：组件按内容定高、把多余高度均分下去；正文止于页高 75% 以上的页 `inspect` 会警告，先想能不能加图、加证据，再问用户是否合页，不靠拉大字号和行距凑。

### 红字结论

判断的形式：现状或问题，加上需要什么。数量本身是事实时才写数量。

| 类型 | 例子 | 处理 |
|---|---|---|
| 带事实的判断 | 社区公共服务设施覆盖率不到一半，存量空间有挖潜余地 | 留 |
| 把本页内容压成一行 | 从编制到评估全过程防范：定下限、记台账、触线转档、失衡暂停 | 改写成判断，或删 |
| 条数加缩写 | 某类目标 11 条：转研发，转物流，转商业 | 改写成判断，或删 |
| 金句和语病 | 改变越根本，程序越严格；四类诉求：推动空间供给能力…… | 优先改 |

- 一句说一两件事。放不下就少说一件事，不压词。
- 不写“本页讲什么”，不写解说句式。
- 上级或同事亲手改过的句子，优先用他们的原话。

### 页面绝不出现

免责、口径说明、待定核查和自我解说不是汇报内容（决策 16）。逐句问：这句在讲项目和政策，还是在替我们解释、免责、澄清、提前挡问题？后者删掉，要留的放备注。

| 类型 | 不写 |
|---|---|
| 免责和口径说明 | “示意图，边界以正式图层为准”“仅供参考”“不作为划界依据”“口径说明”“经概括处理”“未经核实”“精度有限” |
| 待定和核查 | “这一组待定”“暂不讨论，待确认”“待补”“官网标有效”“状态列” |
| 解说和自我澄清 | “这条和上一条不冲突”“不是分区统计的数字”“注：……”“本图表达……”“图中红色表示……” |
| 反复声明适用范围 | 同一条适用范围写在多页，全册最多留 1 处 |
| 替未办理打招呼 | “方案尚未办理”：性质写在三级标题里，正文不重复 |

缺的内容直接不写。“假设情形”“按指南推演”只放三级标题。可以留的：负面清单的条目本身（不可转、禁止）、政策原文里的限制、数据许可署名（整行以 `©` 开头，或“数据来源：”“底图来源：”后只跟来源名称）。

**检查。** 前三类按 GIS 系列统一的清单查（`src/plan_deck/words.py` 的 `BANNED`；gis-plugin 的产物用语 hook 按同一份清单兜底）：`inspect` 和 `audit` 报为 `problems`，退出码 1。逐行查页面上的文本框和表格；备注、隐藏页、版面外的草稿不查。署名行只放行解说类，后面跟了“仅供参考”这类照样报。词表之外的换个说法同样不写，还是要逐句读。

**改已有稿。** 原稿里本来就有的这类文字也会报出来。照样删，要留的移到备注；不是这次写的不算理由，也没有绕过的参数。删了以后版面空出来或页面意思变了，报告给用户。

### 加粗与标红

规划汇报的正文几乎每段、每条都有一处强调色：扫一眼红字，就知道这一条讲什么。这是汇报对象的阅读习惯，按条目加，不按页数限量。分三种写法：

| 写法 | 用在哪里 | 例子（引号里是要加的部分） |
|---|---|---|
| 强调色加粗 | 冒号前的引领词 | “主要构成：”“总体判断：”“核心结论：” |
| | 列举的类别名（破折号前） | “① 实施方案类——明确年度任务和责任分工”中的“实施方案类” |
| | 没有引领词的句子里“讲的是什么”的核心短语 | “各地政策在适用情形、核算标准和审批程序等方面规定较细”中的“适用情形、核算标准和审批程序” |
| | 关键数字、底线词、结论性短句 | “86.5 公顷”“不得”“不予办理”“符合清单的项目视为符合详细规划” |
| | 定义句里的重点 | “混合用地是指一宗用地内兼容两类及以上功能的用地”中的“兼容两类及以上功能” |
| 正文色加粗 | 次一级重点：已经有一处强调色的条目里还要点出的部分 | “主要涵盖：”后列了五项，与本课题最相关的两项加粗，其余不加 |
| 标题色加粗 | 栏名、小标题；罗列性的引领词 | 一栏里每条都以文号开头（“某市政办发〔20XX〕N 号：”） |

判定：

- **引领词**：冒号前 20 字以内，且冒号前没有逗号；有逗号说明冒号前是整句，不算引领词。同一栏里规则一致，不能有的标有的不标。
- **罗列性的引领词不算引领词**：一栏里每条都以文号、地名、年份开头时，这些开头标红就整栏变红，改用标题色加粗。
- **不标红**：页面标题、栏名、小标题、栏下的副题；已经用强调色大号数字的地方，正文里不再重复标红；实色块上的字，重点用白色加粗。

数量：

- 按条目计，一般每段、每条一处；一段里强调色可占两三成字数。
- 不整段标红，通栏说明里至多一句结论标红；不整栏标红。`plan-deck inspect --style` 对这两种情况给警告：一段 40 字以上、强调色占八成以上；一个文本框 3 段以上、强调色占一半以上。
- 表格、图示旁的正文、手工画的页面同样要标。不走运行时 `text` 写 run 时，标红不会自动带上，要逐条过一遍。`inspect` 对正文 200 字以上却完全没有强调色的页给警告；这是线索，手工稿不少页本来就不标红（真实汇报试跑约一到三成的页会报），新做和改过的页才按它补。

正例（运行时 `text` 里 `**…**` 是强调色加粗，`__…__` 是正文色加粗，`^^…^^` 是标题色加粗）：

```
**总体判断：**各地已从单项试点转向系统推进，但实施路径仍不完整。
各地政策在**适用情形、核算标准和审批程序**等方面规定较细，监管规则相对薄弱。
① **实施方案类**——明确年度任务和责任分工，多以一年为周期。
**底线要求：**用途转换后，主导功能的建筑面积比例**不得低于 50%**。
**主要涵盖：**__用途转换与功能兼容__、容积率核算、审批程序和监管规则。
^^某市政办发〔20XX〕N 号：^^明确混合用地的适用情形和办理程序。
```

反例：

- 每页只标两三处：试做时照这条做，用户认为太保守，大多数条目没有落点。
- 引领词用标题色加粗：原稿的习惯是强调色，标题色留给栏名和小标题。
- 一整段、一整栏都标红，或一栏连续五个文号都标红：处处强调，强调就失效了。

### 标题

规划汇报靠结构清晰。标题说明这页是什么，全册标题连起来读就是一份目录；解释和发挥都是讲解员的话，放正文或讲稿。

- **主标题**：写“主题”，或“主题：范围或类型”，如“三类转换的边界：兼容、混合、变更”。并列的页用同一种句式，如“土地用途转换：某物流园”“土地功能混合：某船厂片区”。也可以写带事实的结果句，如“旧产业区更新潜力空间为 12.6km²”。
- **副标题默认不写**（红字结论另有位置，不走副标题），只有三种情况才写：同题多页要区分（环渤海、长三角）；要声明页面性质（按指南推演、假设情形）；要交代口径或数量（按计容建筑面积比例划分；18 个省 · 52 个市 · 190 项政策）。
- **问题页、结论页**：内容本身就是一句判断，可以用陈述句，如“土地变更流程复杂，转换程序比例不清晰”。用户把节点名定成论断句时照写。

| 不用 | 用 | 毛病 |
|---|---|---|
| 地价补缴规则：让企业事先算清“经济账” | 地价补缴规则 | 口号 |
| 立体化开发管理：向立体空间要效益 | 立体化开发管理 | 口号 |
| 清单与控规的分工：控规定“是什么”，清单定“怎么变” | 清单与控规的分工 | 引号造对仗 |
| 三清单回答三个问题：能否转、转什么、怎么转 | 三清单：能否转、转什么、怎么转 | “X 回答 Y”的解说腔 |
| 土地处置方式：按三种情形定供地路径，补齐个案处置条件 | 土地处置方式：规则要点 | 把正文结论搬进标题 |
| 副标题：按指南推演：编制时两次触发清单，把混合写进图则备注，项目实施时不必再修改控规 | 副标题：按指南推演 | 把正文结论搬进副标题 |
| 副标题：按比例划界：比例越高，改变越根本，程序越严格 | 副标题：按计容建筑面积比例划分 | 解释和发挥 |
| 副标题：调研梳理的核心发展方向 | 删去 | 没有信息 |

### 省略和用词

规划人的稿子也省，省的是虚词，用的是行话；AI 味的稿子省掉的是用地类型、对象和主体，用的是口语动词（决策 17）。句子短本身不是问题。

| 省得怪 | 例子 | 改成 |
|---|---|---|
| 单字动词接术语 | 转商业、改研发、走备案、定比例 | 转为商业用地、调整为研发功能、办理备案、确定比例 |
| 讨论口语 | 走规划修改；走程序；动了法定内容；管到；只管；靠控规修改；补不补；没写到；碰红线；算账；不算 | 按法定程序修改控规；履行程序；涉及法定内容调整；适用于；依靠控规修改；是否补缴；未列明；触及红线；测算；不按……管理 |
| 现场造缩略 | 转经营、不补、免许可、闲置盘活、触线转档 | 调整为经营性用途、不补缴、无需规划许可、闲置资产盘活、达到预警线的转入下一档 |
| 条目记法进叙述句 | 局部改商业（在句子里） | 闲置办公建筑局部调整为商业、商务功能 |
| 一句塞太多事 | 按图则、清单、比例分流办理，结果入台账和一张图，修编时纳入 | 分两句，或少说一件事 |
| 省掉读者没有的上下文 | 讨论时说过的前提，到页面上只剩结果 | 写出情形、主体或程序、结果 |

常用替换：走→办理、按……程序；动了→涉及调整；管→适用于；定→确定；补不补→是否补缴；靠→依靠或删；缺→缺乏；出→制定、印发；建筑的改→调整为；用地的转→转为。

- **动词用双音节和制度动词：** 调整为、转换为、办理、适用于、涉及、确定、对照、补缴；明确、细化、统筹、衔接、引导、保障。
- **缩略只用文件或行业已有的说法：** 控规、工改工、公配、商办、保租房可以留；不确定时查项目文件。
- **政策原文的句式：** 情形 + 主体或程序 + 结果。如“现有配套设施已满足地区需要的，经区政府批准，可调整为经营性用房”。
- **不写短句映射：** 不用“问题 → 做法”两列短句对短句，先写文件和做法，再写本地。
- **不用逗号硬并列：** 用“的”“和”“并”“按”把句子接起来，写出条件和结果。
- **不算问题：** 清单条目和“条件和依据”栏、政策摘录和文件对照表、流程图节点、表头、图注、数字。这些本来就短；要改的是这些页里的汇总句。
- **事实和条款不变：** 用文件里的正式说法，改的是说法，不是内容。

`audit` 会列出部分写法，只是线索，清单条目里的可以留。

### 措辞

**页面的读者也没参加过讨论。** 词表挡不住近义句，写完要逐句读：没参加讨论的人读得懂吗？删掉这句会损失信息吗？

| 雷 | 不用 | 用 |
|---|---|---|
| 同事的问题照抄成小标题 | 怎么判；怎么写；在编制的哪个环节触发 | 复合区的判定；备注示例；在编制中的引入环节 |
| 引用听众看不到的东西 | 查相容性参考表（在隐藏页） | 写成页面自身能读懂的说法 |
| 没有来源的新词 | 自造的“本地条件” | 先问用户，或用材料里的说法 |
| 讲稿里的内部话 | 体现工作扎实；便于甲方对照 | 只写讲的内容 |

规划汇报有固定的话语体系（`design-principles.md` 特点 6）。下面是改稿中用户否定过的写法：

| 不用 | 用 |
|---|---|
| 本节看点；本章回答四个问题 | 不单列“看点”；本章主要研究以下四个问题 |
| 本章结论 | 本章小结 |
| 解决：土地用什么方式供出去 | 用于明确土地的供应方式 |
| 把“程序最简”“最常用”“主通道”做成标签块 | 写进正文的句子里，或不写 |
| 完整工具箱（标题） | 写实际内容，如“作用尺度、比例与办理通道” |
| 页面上写“见第 N 页” | 不写，页序一调就对不上；`inspect` 会警告 |
| 抓手、痛点、赋能、闭环、底板、突破口、颗粒度、松紧度、防火墙、绿色通道、政策工具箱 | 措施、突出问题、支撑、全过程、借鉴重点、简化审批、政策体系 |
| 英文副标题（PROBLEM 01、Mixed-Use Development） | 删去 |
| 口号式副标题（“先看别人怎么做……照搬不了”） | 写本章各节名 |
| 箭头短语（“→ 账算清了才有人来”） | 完整的陈述句 |

新写的页面照右列写。接手的旧稿里已有这类词，用户没要求就不主动改，列出来问。

### 改完通读：整页连贯，一件事只说一次

单句的毛病上面几节管；这一节管一页之内、页和页之间。改稿时只盯着一个文本框改，最容易出这几种毛病：前一句提一个做法，后一句写出不允许它的条件；同一个意思在红字结论、正文、底栏各说一遍；新定的口径在十几页上各补一句；旧句不动，后面加括号解释。改完不要只看改过的框，按下面的顺序把整页、整节读一遍。

**一、每个口径只有一个主场页。** 新定的口径、新加的内容，在它的主场页写全：定义、条件、例外、依据都在这一页。其他页只在原有说法和新口径冲突时改字，不另加说明句；和这条口径无关的页不动。拿不准放哪页时，放在读者第一次需要它的那一页，后面的页沿用同一个说法。

**二、页内分层，每层不重复上一层。** 红字结论是本页的一个判断；小标题和正文是支撑它的条件、做法、例子；底栏和注释只放正文放不下、又必须有的补充，不把结论再说一遍。同一个意思在一页里出现了两次，删掉下一层的那一次。

**三、前后不能互相否定。** 提出一个做法，后面又写出不允许它的条件，读者只看到矛盾。要么把条件写具体（这个做法在什么条件下可以），要么不提这个做法。底线约束（生态保护红线、城市绿线、城镇开发边界等）是规划体系本身的条件，可以写，不算防御性用语，但要和前文对得上。

**四、不打补丁。** 旧句和新口径对不上时，把这句重写，不在后面加括号解释，也不靠“亦可”“另”“但”接上。一句话要靠括号才说得清，说明它在讲两件事，拆开写或少说一件。

**五、放不下时先保什么。** 按这个顺序保留：规则本身 → 适用条件和例外 → 依据 → 说明和例子。放不下的从后往前删，不缩字号，不压词。

| 毛病 | 原文 | 改法 |
|---|---|---|
| 前后互相否定 | 研究在防护绿地兼容风电设施；须严守城市绿线 | 写成条件：防护绿地按城市绿线管理规定论证；或不列防护绿地 |
| 同一意思说三遍 | 红字“超过 30% 只能临时转换”，正文、底栏再各写一遍 | 红字留判断，正文写条件和期限，底栏删 |
| 卡片标题和正文重复 | 标题“本次非重点”，正文“本次不作为研究重点” | 标题写处理方式，正文写依据 |
| 新口径铺满全册 | 一个研究方向在六页上各补一句 | 只写在定义页和专门那页 |
| 括号补丁 | 按本路径办理（30% 以内亦可选择） | 30% 以内的也可按本路径办理 |

审核对比 PDF（`plan-deck compare`）也能帮着查：红框圈到了没打算改的地方，或者同一个意思在好几页都被圈出来，多半犯了上面的毛病。

## 分析图与信息图

好的分析图不靠效果图，而是每张图只说一件事，全册用同一套画法反复讲。以下做法来自用户推荐的参考文本，plan-deck 能用可编辑形状画出来；地图本身的画法交给 gis-composer（`map-types.md`）。

- **一页一张主图**：`split` 版式里大图占页宽六七成，可以出血到页边；文字栏是“问题或论断标题 + 一段说明”，不再堆别的元素。
- **问题用问句提出**：“挑战 N：……如何……？”，左栏说明，右侧一张图回答。
- **结构先拆后合**：先用几张同底形的小图各讲一项结构要素，再用一张综合图合起来，最后用一句数字概括（“两带三廊三极”），并逐项写“两带：……三廊：……”。结构图用简化成几何形的基地轮廓，比真实底图讲得清楚。
- **同底图小图组**：同范围、同底形、同尺寸的几张小图并排，每张只亮一个主题；用在 `columns` 版式里时，每栏是“■ 标题 + 短文 + 小图 + 示意剖面”，栏与栏只靠对齐和留白分开，不加框。
- **大号数字**：细字重、强调色的大号数字配一行说明；数字要落在空间上时，用引线指到图上的位置。
- **几种常用信息图**：环形图或进度环配一个大数字；“A / B / C”分组用括号连到要点列表；前后对比用两根堆叠柱，中间写 VS；比值（如拆建比）画成两端圆、中间一条横条。
- **前后对比小插图**：一对同样画法的小图加箭头，表示“现状 1.0 → 规划 2.0”，同一组里各对的画法一致。
- **一套图标贯穿全册**：每项主张或策略配一个线性图标，后文相关页在角上重复出现，起导航作用；全册图标同一线宽、同一风格。
- **焦点标记统一**：要强调的地方用虚线圆圈出，不另加文字框；基地用醒目的范围线和“SITE”类标记。

不要学的：拼贴照片配印章式大字、艺术字，在实用汇报里显得花哨。

## 品质从哪里来

规划院汇报的问题不在配色，而在一致性：框图临时手搭，同一概念各页画法不同，对齐靠目测。视觉系统、网格和标题层级由运行时保证，下面这些要自己做到：

- **统一的图示母题：** 同一种图示风格、同一套图标，例如几项主张各配一个图标，贯穿后文。
- **定位小图：** 空间相关的页在角上放一张小的全区图，标出本页位置。
- **节奏：** 密集的分析页之间穿插整页大图（愿景、章节、效果图）。
- **地图风格化：** 淡化底图只突出主题要素，或深色底加亮色流线，不直接套 GIS 默认样式（gis-composer 出图时定）。不讲美观、只求投影上显眼的实用汇报另有一套高饱和画法（`vivid-report`），见 `map-types.md`“鲜艳实用汇报的地图”。

工具做得过于整齐时，定稿后用去 AI 味收尾处理（`humanize.md`）。

## 规划汇报的常见做法

供定视觉系统时参考，不是规定：

| 项 | 观察 |
|---|---|
| 页面 | 尺寸各项目不同（A3 横版、几种 16:9 都有），白底 |
| 字体 | 中文几乎都用微软雅黑 |
| 字号 | 以 52.8×29.7 cm 页面计：标题 24–28 pt，正文 14–20 pt，注释 10–12 pt |
| 配色 | 规划院汇报多用深蓝标题、蓝青主色、红色强调；竞赛和高水准的汇报也有白底黑字、几乎不用颜色的 |
| 结论 | 多数页面的结论直接用强调色或 ■ 条目写在正文末尾，不加框 |
| 地图 | 卫星底图 + 红色范围线 + 永农黄色叠加是方案页的标配 |
