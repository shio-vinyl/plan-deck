# 正文做法

“每页三层”（`visual-language.md`）的第二层是放大的重点：整块实色、大字、粗箭头，一眼看到本页最重要的两三件事。常用的几种做法和图示做成了运行时组件，本文写每种用在什么内容、怎么调用、什么时候不用。

做法来自用户认可的一份政策研究汇报的工作稿。学的是要求，不是样子：先想这页的观点，再按内容选做法；内容不合适就写正文或表，不为了用组件改内容。

## 按内容选

| 内容 | 做法 | 组件 |
|---|---|---|
| 几个环节、文件、案例各说一段，每条有短名 | 标签行 | `rows` |
| 两到四类问题或做法并列，各有一段说明 | 实色栏头并列 | `columns` |
| 几栏或一张图的共同结论、共同要求 | 结论通栏，可加实心箭头 | `banner`、`block_arrow` |
| 有先后的程序、阶段 | 粗箭头链（只有环节名）、实色节点链（节点下挂说明） | `chevrons`、`flow` |
| 几个部门在几个阶段的分工 | 泳道 | `lanes` |
| 政策依据、上位文件、外地做法的原文 | 文件摘录图 | `excerpt` |
| 逐行比对：事权、清单、几个案例的同一组要素 | 矩阵表 | `matrix` |
| 按程度分档、逐级加严 | 分档台阶 | `steps` |
| 在算账 | 账算式 | `ledger` |

一页一般用一到两种。放大的只是两三件事，其余是 12—14 磅的密集次要信息，条款、时间、数字、案例都留着。相邻几页不要都用同一种。

## 共同的约定

- **字号**：色块里的关键词用 `key`（预设里 18 磅，19.05 cm 页高），三五个字的大字栏头用 `figure`（30 磅），正文 `body`。老的 `style.json` 没有 `key` 时退到 `heading`。
- **铺满**：高度按内容定。给 `bottom` 的组件默认铺到版心底，多余高度均分；下面还要放东西时给 `bottom=<y>`，不铺给 `bottom=False`。
- **颜色**：类别色从 `classes` 取。`colors='类别'` 给方案名时逐项轮流取这组颜色；条目最后多给一个颜色可以单独覆盖，如 `('区政府审定', 'emphasis')`。同一种颜色在同一页、相邻页只表示一类内容，运行时会查。实底上的字按底色深浅自动用白字或正文色。
- **放不下**：记进 `deck.warnings`。拆分节点、少说一件事或换做法，不缩字号。
- **标红**：条目里的文字照常按条目标红（`**…**`）；色块上的字不标红，重点用白色加粗。

完整的可运行示例：`examples/patterns_deck.py`（虚构内容，每种做法一页）。

## 标签行 `rows`

左边实色块写短名，右边正文，自上而下 2—5 行。

- **用在**：并列、各有短名的条目，如土地收储的五个环节、四份国家文件、三个案例的做法。短名一行不超过六个字，可以两行。
- **参照**：土地收储流程页，五个环节排成一列标签行，右边配费用分类表和现场照片。
- **不用**：
  - 不当每页的默认做法。去 AI 味的统计里，“左色块＋右底框成行”的页 AI 稿占 32%，人做的稿子 0—6%。一册里用它的页超过一成，`inspect` 会警告。
  - 条目没有短名，或短名只是“一、二、三”：写成正文条目。
  - 内容要逐格比对：用矩阵表。
- `body='tint'` 正文垫浅底，是工作稿的样子；`body='plain'` 白底，行间一条细线。

```python
p.rows(x, y0, w, [('申请与\n权属核实', '核实土地及地上物权属、面积、四至，出具**测绘报告**。'),
                  ('方案审批', '拟定整备方案，报市土地管理委员会批准。')])
```

## 实色栏头并列 `columns`

2—4 栏等宽，栏头整块实色，下面是说明，底框铺到底。

- **用在**：同类的几项并列，各有一段说明，如三类存在问题、三类用途转换。名称本身是判断、只有三五个字时用 `head_size='figure'` 写大字；`subs` 给栏头下一行副题（标题色加粗）。
- **参照**：存在问题页，三栏大字栏头（文件到期、规则偏窄、逐案决定），下接实心箭头和一条结论通栏；行政风险页，按办理环节分五栏。
- **不用**：几项是先后关系（用节点链）；各栏长短悬殊（写正文）；只为了把文字分成几块。

```python
cb = p.columns(x0, y0, x1 - x0, [('文件到期', '…'), ('规则偏窄', '…'), ('逐案决定', '…')],
               head_size='figure', subs=['基础文件到期', '现行规则覆盖不足', '其余情形靠逐案决定'],
               colors='类别', bottom=y1 - 2.2)
p.block_arrow((x0 + x1) / 2 - 1.2, cb.bottom + 0.1, 2.4, 0.7)
p.banner(x0, cb.bottom + 0.9, x1 - x0, '需要一套事先明确、覆盖存量转换的清单和配套规则')
```

## 结论通栏 `banner`、实心箭头 `block_arrow`

- **用在**：几栏或一张图的共同结论、共同要求，一页至多一处。上面是几栏时，中间放一个下箭头。
- **不用**：每页都在页底加一条（`visual-language.md` 列为 AI 的写法）；红字结论已经说过的话。

## 粗箭头链 `chevrons`、实色节点链 `flow`

- **用在**：真正有先后的程序。只有环节名时用粗箭头链；节点下要写说明（这一步对应哪项机制、哪份文件）时用节点链。重点环节用实色，一般环节用浅色，如 `('区规资备案', 'fill')`。节点之间是 3 磅粗箭头。
- **参照**：项目办理页底部的五段箭头链，后两段着强调色；办理流程衔接页，两条节点链，签订协议、补缴价款、变更登记三个环节着色，节点下写对应的机制名。
- **不用**：没有先后的并列项（用栏头并列或标签行）；超过九个环节（分两行或拆页）。

## 泳道 `lanes`

- **用在**：几个部门或主体在几个阶段的分工：谁收集诉求、谁审查、谁决定。行是部门，列是阶段；节点可以跨几个阶段；最后的决定用 `'emphasis'`，只写配合事项的用 `'plain'`。连线的端点粘在节点上，在 PowerPoint 里挪节点时跟着走。
- **参照**：部门分工体系页：属地、规资部门、产业部门、联审部门、区政府五条泳道，八个阶段。
- **不用**：只有一个主体（用节点链）；阶段超过八个或部门超过六个（拆页）。

```python
p.lanes(x0, y0, x1 - x0, y1 - y0,
        [('属地', ('类别', '一')), ('规资部门\n牵头办理', ('类别', '五'), 1.6), ('区政府', 'emphasis')],
        ['诉求收集', '申请受理', '初审会商', '联合会商', '审定'],
        [(0, 0, '收集诉求'), (1, 1, '核对主体、权属'), (1, (2, 3), '组织联合会商'), (2, 4, '审定', 'emphasis')],
        links=[(0, 1), (1, 2), (2, 3)])
```

## 文件摘录图 `excerpt`

- **用在**：政策依据、上位文件、外地做法的原文。截图裁到相关条款，要点用红色虚线框圈出，图注写文件全称和文号；旁边的摘要和框出的条款一一对应。裁剪和框都按原图的比例给，原图留在 pptx 里，PowerPoint 里还能调。
- **参照**：国家层面关于清单的规定页：左边四条标签行写文件和要点，右边文件截图框出两处。
- 红虚线框是证据物的一部分，工作稿就加，不算去 AI 味的手工标注（`humanize.md`）。
- **不用**：截图缩到看不清（改用摘录框写原文）；页面上没有和它对应的文字。

## 矩阵表 `matrix`

- **用在**：逐行比对：规划编制审批事权、转换清单、几个案例的同一组要素。两行合并表头（`header_rows`、`merges`），行头一列实色（`row_heads`），按类别给列头上色（`col_heads`），高亮格（`highlight`，浅红底强调色）。默认在正文 1—1.25 倍的字号里取放得下的最大值，多余高度均分给各行，铺到版心底；选了多大记在 `deck.fitted`。
- **参照**：编制审批事权页，两行表头，牵头编制部门和审批人员两行高亮；转换清单页，三类转换的行头一列各着类别色；支撑机制落地页，五个案例的列头各一色。
- **不用**：清单以外的内容硬排成表（程序和分工用图示）；只有两三行（写正文）。

## 分档台阶 `steps`

- **用在**：按程度分档、逐级加严：未触及预警线、达到预警线、突破下限、评估发现失衡。从低到高逐级升高，颜色从浅到深（`colors='分档'`），块下写这一档怎么办理；给了 `h` 时说明垫浅底一直铺到底（`body='plain'` 只有字）。档名较长时用 `size='heading'`。
- **参照**：功能失衡防范措施页的下半部分。
- **不用**：档与档之间没有程度递进（用栏头并列）。

## 工作稿和去 AI 味版的分界

参照稿有工作稿和去 AI 味版两版，去 AI 味时只换了颜色、改了形。照着学之前先查一页出自哪一版：同一页按文字找到两版的对应页，比配色和版面。工作稿照左列做，组件的默认值也是左列；右列只在用户说定稿以后的去 AI 味版里做（`humanize.md`）。

| 工作稿就有，组件默认 | 去 AI 味版才改 |
|---|---|
| 页眉、红字结论 | 红字结论不必每页同一位置 |
| 14 磅以上的中间层（参照稿两版都占正文约两成） | 大字、大数字随内容再放大 |
| 版面铺到版心底（参照稿两版的未铺满页都在 3% 以下） | 图放大、伸出版心 |
| 标签行、栏头、节点链、泳道、台阶、矩阵表这些结构 | 标签行去掉浅底或改成色头条；框按字量定宽 |
| 项目自己的配色（预设里是深蓝、蓝灰、砖红，浅底偏蓝灰） | 换 Office 默认色，浅底改中性灰，线改黑或灰 |
| 文件图上的红虚线框 | — |

## 检查

`inspect` 每页查，都是警告：

- **正文止于页高 75% 以上**：铺到版心底（组件给 `bottom`）、加图，或问用户是否和相邻节点合页。封面、目录这类字少的页和满版图页不查。
- **缺中间层**：正文 200 字以上却没有 14 磅以上的字（页高按 19.05 cm 折算），图占页面不到 15% 时才报。
- **箭头从字上压过**：带箭头的连线压在文字上（端点附近 0.3 cm 不算）。
- **标签行过多**：一册里用左色块＋右底框标签行的页超过一成。

`audit` 加两项全册指标，参考范围来自五份人做的规划汇报：正文里 14 磅以上字的比例（0.38—0.63；同口径下 AI 做的工作稿 0.14—0.22），正文止于页高 75% 以上的页（0—2%）。只作线索，不为凑数字改页面。

`style check`：`colors` 的键、`classes` 的类别名按色相起名（navy、lightBlue、深蓝）时警告；同一个色值在几组类别色里都用时给 info。出页时同一颜色在同一页或相邻页表示两类内容，`deck.warnings` 警告。
