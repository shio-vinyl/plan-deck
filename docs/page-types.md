# 页面类型库 v0

页面类型（page type）描述**一页要干什么、由哪些槽位组成**，与版式（layout）分开：版式只有固定的几种（见 `visual-language.md`“版式清单”），一个页型可以用其中一种或几种。页型本身决定这一页排多密；项目视觉系统决定它长什么样（见 `design-principles.md` 决策 2）。页型 id 用于形状命名（见 `architecture.md`）。

页型库是开放的参考，不是必选项：没有哪份汇报必须包含哪些页型。起稿时按结构树的需要选用、组合，遇到这里没有的内容可以新增页型。

## 通用槽位

除结构类页面外，内容页都带这些槽位：

| 槽位 | 说明 |
|---|---|
| `parent-title` | 页眉第一行，上级节点名，与 `title` 同色同粗、大一级；总览页没有这一行 |
| `title` | 结构大纲里的节点名，一字不差（含编号），见设计决策 11。节点名默认是“编号 + 主题”，问题页、结论页或用户指定时才是论断句，写法见 `visual-language.md`“标题” |
| `subtitle` | 默认不写。只用于同题多页的区分、声明页面性质、交代口径或数量（`visual-language.md`“标题”）；agent 想补充的判断放正文或讲稿，不写在这里 |
| `source` | 默认不放；依据写进正文 |
| `page-no` | 默认不放，整份汇报定稿时按需要加 |

## 结构类

| id | 名称 | 槽位 / 结构 | 常用版式 |
|---|---|---|---|
| `cover` | 封面 | 主标题、“——”副标题、阶段标签（初步方案汇报 / 阶段成果 / 第 N 次汇报）、委托方、编制单位、日期；也可用全幅效果图 + 口号 | 结构页 |
| `toc` | 目录 | 章节列表；文本全本带页码的完整目录。默认铺满版心：各章一行，均分版心高度；左侧深色章号块，右侧章名和各节名（节名等宽分栏，顶部短色线），过长的节名按意群手动断行 | 结构页 |
| `chapter` | 章节页 | 序号（汉字或数字）+ 章节名，可列本章小节；变体：目录原样重放、高亮当前章 | 结构页 |
| `section-overview` | 节总览页 | 节一级中间节点带的一页总览：通栏说明 + 3–4 栏要点，把本节后面各页汇总一遍；见下文 | `columns`、`table` |
| `chapter-summary` | 章小结页 | 照片满版 + 居中的大字结论句 + 短线 + 一句副句；见下文 | `full-image` |
| `overview` | 概况与范围 | 规划范围、期限、面积、人口、经济等基本数，配范围图；放在目录前或第一章 | `split` |
| `work-process` | 工作组织与进展 | 组织架构框图 / 会议与调研时间线 + 现场照片 / 调研量化（“X 人 + X 组 + X 阶段”）/ 已完成工作框图 | `diagram`、`gallery` |
| `revision` | 修订分隔页 | 一句话说明改版原因和日期，后接修订版页面 | 结构页 |
| `end` | 致谢页 | “谢谢，敬请批评指正！” | 结构页 |
| `backup` | 备用页 | 任意页型，隐藏，放在致谢页之后 | 同原页型 |

## 节总览页、研究问题页、章小结页

这三种页面在章、节的开头和结尾，容易做成通用 PPT 的过渡页。下面的做法和反例来自改稿反馈。

### 节总览页（`section-overview`）

节一级的中间节点带的一页总览（设计决策 11），放在下级各页之前。大纲规则不变：中间节点不出页，或带一页总览；不另做只有导语的节首页。

- **页眉**：统一页眉，标题照节点名，不另写概括句；概括放在下面的通栏说明里。用户把节点名本身定成“节名：一句概括”时照写。
- **正文**：一条通栏说明，下面 3–4 栏要点（`columns` 版式），铺满版心。每栏依次是色线、栏名、副题（涉及的地方或关键数字）、要点，把本节后面各页的内容汇总一遍。
- **阶段条**（可选）：一条横跨各栏的阶段条，例如“规划编制阶段 / 规划实施阶段”，把各栏归到阶段下。
- **汇总表**：本节后面是一组同结构的数据表时，总览做成汇总表（`table` 版式），例如行是地区、列是政策类别，单元格写条数、出台年份。
- **副题折行**：副题折成两行时，下面的要点随之下移。按字宽估副题行数再定要点的起点（运行时 `text` 返回的 `Box.bottom` 接着排），不按一行的高度写死。
- 栏里的文字照常加粗标红（`visual-language.md`“加粗与标红”），栏名和副题不标红。

不用的做法：

- 白底，只有节名、一条短色线和两三行导语：页面太空。
- 用章节页的样式（深色竖条、大号章号）：和章节页同构，几个节连着出现同一个大号章号，节奏乱。
- 靠“本节看点”标签、大数字、卡片填空白：像信息图。

### 研究问题页（`questions`）

一章开头列出本章要研究的问题，是这一章的总览页；页眉照节点名。

- **引导句**：“本章主要研究以下 N 个问题”，措辞正式，不用“本章回答 N 个问题”“本章看点”。
- **问题**：编号陈述句，句末不加问号，例如“一、存量建筑功能转换的适用情形与审批程序”“二、混合用地的比例与兼容性规定”。
- **设问变体**：上部摆已知条件（现状、上位要求），下部一句“需要研究的问题”，放在分组底里（浅色填充、无边框，`visual-language.md`“框和卡片”）。
- 不用大号“？”、大三角箭头、问号图标这类装饰，也不用标签块和卡片。

单页分析图的问句标题（“挑战 N：……如何……？”，`visual-language.md`“分析图与信息图”）不受影响；列问题清单的这一页用陈述句。

### 章小结页（`chapter-summary`）

一章末尾用一页收束。大纲里节点名写“本章小结”（或带编号），不写“本章结论”。

- **照片满版**：照片铺满整页，不画页眉，不加章节标签和图注。照片从项目材料和过往汇报里找，找不到就问用户，不用示意图冒充。
- **结论句**：页面上唯一的大字，用结构页的大字级、白色加粗，水平、垂直都居中于页面中部；下面接一条短线和一句副句。这是许多规划文本的通行做法。
- **衬底**：文字下垫一条上下渐隐的暗带（`band`），中间最深，不透明度约 45%；文字加柔和投影（`label(shadow=True)`）。这是“框不加阴影、渐变”的例外，只用于照片上的字。
- **断行**：结论句按意群手动断行，末行不能只剩一两个字。正例“老城更新的难点不在规模，/ 而在产权与资金的组织方式”；反例“老城更新的难点不在规模，而在产权与资金的组织方 / 式”。

不用的做法：

- 照片上压半页、大块不透明的深色底再叠白字：像宣传海报，不严肃。
- 白底，结论在上、照片在下：结论读起来像标题。
- 结论放在页顶。

## 页型序列

有些内容不是单页，而是固定顺序的一串页面，起稿时按序列排：

| 序列 | 组成 |
|---|---|
| 问题展开 | `question`（问题 N：论断）→ 若干 `evidence`（1）2）3）分项各一页） |
| 方案比选 | 若干 `scheme-compare`（方案一页、方案二页）→ 比较页 |
| 规模测算 | 若干 `forecast`（方法一、二、三）→ 综合取值 → 小结 |
| 重点地区 | 现状三联图 → 规划理念 → 城市设计总图 → 意象参考 → 功能结构 → 景观体系 → 空间效果（带定位小图） |
| 同底图专题 | 同一张底图、同一画幅，连续多页只换专题图层，左栏配数字 |
